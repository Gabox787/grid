# Grid Trading Bot + FastAPI Dashboard

Асинхронный крипто-бот на стратегии **Grid Trading** (`ccxt.async_support` + `asyncio`)
со встроенным веб-дашбордом на **FastAPI**, персистентностью состояния в Postgres
и журналом сделок для честного ROI/винрейта. Готов к деплою на Render как Web Service.

## Как это работает

1. При старте бот берёт текущую цену пары (`SYMBOL`) и рассчитывает уровни сетки.
2. Бюджет депозита делится на **две зоны**:
   - **Core** — основная сетка между `LOWER_BOUND` и `UPPER_BOUND`.
   - **Extension** — резерв *ниже* `LOWER_BOUND`: если рынок падает и собирает все
     Buy-ордера основной сетки, бот не останавливается, а докупает на дальнейших
     откатах уровнями резервной зоны — оставаясь строго в рамках заранее
     посчитанного бюджета.
3. Buy исполнен → сразу выставляется Sell на соседний уровень выше (с тем же
   объёмом). Sell исполнен → Buy на соседний уровень ниже. **Ни одна позиция
   никогда не продаётся по рынку принудительно** — она ждёт свой лимитный
   Sell на нужном уровне сколько угодно.
4. Kill-switch — это **alert-only монитор**, а не "закрыть всё": при выходе
   цены за `LOWER_BOUND` и за границу резервной зоны бот шлёт уведомление
   (в лог и, если настроен, в Telegram) и просто перестаёт открывать новые
   покупки сверх бюджета — открытые позиции не трогает.
5. Состояние (уровни сетки, счётчики, флаги) сохраняется в Postgres при каждом
   изменении. При рестарте/редеплое на Render бот сначала пытается
   восстановиться из БД, затем сверяет восстановленные ордера с реальным
   статусом на бирже (вдруг что-то исполнилось, пока инстанс был недоступен).
6. Каждый филл пишется в таблицу `trades` — основа для честного ROI/винрейта
   и CSV-выгрузки.

## Переменные окружения

| Переменная              | Описание                                            | По умолчанию |
|---------------------------|--------------------------------------------------------|--------------|
| `EXCHANGE_ID`              | ID биржи в ccxt (`binance`, `bybit`, ...)               | `binance`    |
| `API_KEY` / `API_SECRET`   | Ключи биржи (только права на трейдинг, без вывода!)   | —            |
| `SYMBOL`                   | Торговая пара                                           | `BTC/USDT`   |
| `UPPER_BOUND`               | Верхняя граница core-сетки                            | `66000`      |
| `LOWER_BOUND`               | Нижняя граница core-сетки                             | `60000`      |
| `GRID_LEVELS`               | Количество уровней core-сетки (мин. 2)                | `10`         |
| `DEPOSIT_USDT`              | Сколько всего денег выделено боту                     | `2000`       |
| `CORE_USAGE_RATIO`          | Доля депозита на основную сетку                       | `0.6`        |
| `EXTENSION_USAGE_RATIO`     | Доля депозита на резерв для откатов ниже LOWER_BOUND  | `0.2`        |
| `EXTENSION_DROP_PCT`        | На сколько % ниже LOWER_BOUND тянется резервная зона  | `0.15`       |
| `EXTENSION_LEVELS`          | Количество уровней в резервной зоне                   | `5`          |
| `POLL_INTERVAL`             | Интервал опроса ордеров, сек.                          | `10`         |
| `DRY_RUN`                   | `true` — без реальных ордеров (симуляция по цене)      | `true`       |
| `PLACE_INITIAL_SELLS`       | Выставлять ли Sell-ордера при старте                  | `true`       |
| `DATABASE_URL`              | Postgres connection string (персистентность)          | не задан → работа только в памяти |
| `FEE_RATE_PCT`              | Оценка комиссии, если биржа её не вернула (0.001 = 0.1%) | `0.001`   |
| `STALE_RESUME_THRESHOLD_SECONDS` | DRY_RUN: простой дольше этого — пересобрать сетку у текущей цены, а не марафонить фиктивные филлы | `1800` |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Push-уведомления + команды (owner-only) | не заданы → только логи |

### Депозит $2000: как считается бюджет

```
core_capital      = DEPOSIT_USDT × CORE_USAGE_RATIO         = 2000 × 0.6 = $1200
extension_capital = DEPOSIT_USDT × EXTENSION_USAGE_RATIO    = 2000 × 0.2 = $400
reserve (нетронутый) = DEPOSIT_USDT − core − extension       = $400

qty_core      = core_capital / sum(цены core-уровней)
qty_extension = extension_capital / sum(цены extension-уровней)
```

Даже в абсолютном худшем случае — если бы цена рухнула и **все** уровни core
одновременно превратились в исполненные Buy — суммарно потратилось бы не
больше `core_capital`. Аналогично для extension. `reserve_usdt` бот вообще
не трогает — это просто запас на комиссии/проскальзывание/ручное вмешательство.

**Пример на $2000** (BTC/USDT ~$63 000, core 60 000–66 000, 10 уровней core,
resize extension на 15% ниже, 5 уровней extension):

| Зона | Диапазон | Капитал | Уровней |
|---|---|---|---|
| Core | 60 000–66 000 | $1200 (60%) | 10 |
| Extension | ~51 000–60 000 | $400 (20%) | 5 |
| Резерв (не трогаем) | — | $400 (20%) | — |

Если цена уйдёт ниже $60 000 и core полностью исполнится — бот продолжит
покупать на откатах вплоть до ~$51 000 за счёт extension-бюджета, при этом
ранее купленные core-позиции **останутся открытыми** и будут ждать своего
Sell-уровня, а не продадутся в убыток.

## Kill-switch (alert-only)

- Цена ниже `LOWER_BOUND` → предупреждение (лог + Telegram, если настроен),
  бот переходит на резервные уровни.
- Цена ниже границы extension-зоны → критическое уведомление "бюджет
  исчерпан, новых Buy не будет", бот продолжает мониторить и ждать
  восстановления цены. **Ничего не продаёт принудительно.**
- Возврат цены выше границ — отдельное уведомление о восстановлении.

Чтобы получать уведомления в Telegram, создайте бота через `@BotFather`,
получите `chat_id` (например, через `@userinfobot`) и задайте
`TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`. Без них уведомления идут только в логи Render.

## Персистентность (Postgres)

На **бесплатных** Render Web Service нет персистентного диска — файл SQLite
стирался бы при каждом рестарте/редеплое. Поэтому используется внешний
бесплатный Postgres:

1. Создайте бесплатную БД на [Neon](https://neon.tech) или [Supabase](https://supabase.com).
2. Скопируйте connection string (обычно вида `postgresql://user:pass@host/db`).
3. Задайте его в `DATABASE_URL` на Render (Environment → добавить переменную,
   как секрет).
4. Redeploy. В логах должно появиться "Подключение к БД установлено, таблицы готовы".

Без `DATABASE_URL` бот продолжает работать как раньше — просто в памяти,
без сохранения состояния между рестартами (на дашборде будет тег "БД: отключена").

## Журнал сделок / ROI / винрейт

- `GET /api/trades` — JSON: последние сделки + агрегаты (`closed_cycles`,
  `win_rate`, `avg_profit_per_cycle`, `total_profit`). Винрейт считается
  только по закрытым циклам (Buy → Sell с известной ценой входа), а не по
  каждому отдельному филлу.
- `GET /api/trades.csv` — полный журнал в CSV, кнопка "Скачать" есть на дашборде.

## Telegram-бот: уведомления и команды

Помимо алертов kill-switch, бот шлёт **push-уведомления на каждый вход и
выход** из сделки — с точным временем, ценой, объёмом, P&L и комиссией — и
отвечает на команды (owner-only, только `TELEGRAM_CHAT_ID`):

```
/status  — цена, статус, бюджет core/extension/резерв, профит, комиссии
/grid    — какие уровни заняты (buy/sell), сколько свободно
/trades [N] — последние N сделок с ценой входа/выхода и P&L (по умолчанию 10)
/pnl     — профит брутто/нетто, ROI от депозита, винрейт, средний профит/цикл
/fees    — суммарные комиссии за всё время
/uptime  — сколько времени бот работает без перезапуска
/pause   — остановить открытие новых ордеров (открытые позиции не трогает)
/resume  — снять паузу
/export  — прислать полный журнал сделок файлом CSV
```

Комиссия считается так: если биржа вернула реальную `fee` в ответе на
`fetch_order` — берётся она; если нет (например, в `DRY_RUN`) — используется
оценка `FEE_RATE_PCT × цена × объём` (по умолчанию 0.1%, типовая спот-комиссия
без скидок).

Настройка: создай бота через `@BotFather`, получи `chat_id` через
`@userinfobot`, впиши оба значения в `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`.
Без них push-уведомления и команды просто отключены — бот работает как раньше.



```bash
git clone <your-repo-url>
cd grid-bot
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
export $(cat .env | xargs)
uvicorn main:app --reload --port 8000
```

Откройте `http://localhost:8000` — дашборд, `http://localhost:8000/api/stats` — JSON.

По умолчанию `DRY_RUN=true`: бот не отправляет реальные ордера на биржу,
а симулирует их исполнение по факту пересечения рыночной цены с ценой
уровня — можно проверить всю логику (включая extension-зону и kill-switch)
без риска для средств.

## Деплой на Render

1. Запушьте проект в GitHub-репозиторий.
2. В Render: **New → Blueprint**, укажите репозиторий — Render подхватит `render.yaml`.
3. В **Environment** задайте `API_KEY` / `API_SECRET` и `DATABASE_URL` как секреты.
4. Оставьте `DRY_RUN=true`, задеплойте, проверьте дашборд и логи.
5. Только убедившись, что грид-логика (включая extension/kill-switch) ведёт
   себя ожидаемо, переключите `DRY_RUN=false` и сделайте redeploy.

## Безопасность

- Используйте API-ключи **только с правами на спот-трейдинг**, без права вывода средств.
- По возможности включите IP-whitelist на бирже.
- Бот использует поллинг (`fetch_order` / `fetch_ticker`), а не WebSocket —
  это `ccxt.async_support`, а не платный `ccxt.pro`.
- Preflight-проверка перед стартом сверяет реальный баланс `USDT` с
  требуемым бюджетом (`core_capital + extension_capital`) — если денег
  меньше, бот не стартует вместо частичного размещения сетки.
